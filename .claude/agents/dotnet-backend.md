## Hard rules
- **Dependency direction inward only:** Api → Application/Infrastructure/Contracts; Infrastructure → Application → Domain/Contracts → Domain. `Domain` has **zero** project/framework deps. This is enforced by NetArchTest in `GameTeam.Application.Tests` — never weaken those tests to pass.
- **Domain is pure:** no EF/HTTP/`DateTime.Now`. Inject `IClock`, use server time.
- **CQRS:** commands/queries + handlers + FluentValidation, MediatR pipeline. Follow the feature-folder layout in `docs/backend/domain-and-application.md` (scaffold in `.templates/backend-feature-folder/`).
- **Application pipeline (Phase 10, closed):** cross-cutting lives in **MediatR pipeline behaviors** (`GameTeam.Application/Behaviors/`), never in handlers — keep handlers thin. Fixed order **Logging → Validation → Transaction → Caching** (`AddApplication`; `PipelineOrderTests` guards it — don't just trust registration order). Validation failure → `Result` error (`VALIDATION_FAILED`), never a thrown exception to the API. Transaction wraps **only** `ITransactionalRequest` (queries never enter a transaction); Caching wraps **only** `ICacheableQuery` (key = name + params + config version); Logging never logs request bodies/PII. Ports (`IUnitOfWork`, `IRepository<TEntity,TId>`, `ICacheService`, `IConfigProvider`) are declared in Application and implemented in Infrastructure (phases 11–12/21); reuse `IClock` from Domain. **Reuse, don't reinvent** these behaviors/ports/`Result`; every new command/query goes through the pipeline. See `docs/backend/cross-cutting.md` §2.5.
- **Persistence (Phase 11, closed):** EF Core/Npgsql live **only** in `GameTeam.Infrastructure` — enforced by NetArchTest `Application_should_not_depend_on_efcore_or_npgsql` (+ Domain purity); never weaken them. Source: `GameTeam.Infrastructure/Persistence/` — `AppDbContext` (its `SaveChangesAsync` override **dispatches domain events** after persist, inside the transaction, via MediatR `DomainEventNotification<T>`/`IPublisher`), `EfRepository<TEntity,TId>` (only `GetById`/`Add`; never leak `IQueryable`/`DbSet`/`DbContext`), `UnitOfWork` (`Begin/Commit/Rollback`; the port has no SaveChanges so **Commit itself calls SaveChanges** then commits the tx). EF mapping = one `IEntityTypeConfiguration<T>` per entity, **explicit `snake_case`** table/column. Connection string from config key `ConnectionStrings:Postgres` (env `ConnectionStrings__Postgres`) — **never hardcode credentials**. Schema changes go through **migrations** (`dotnet ef migrations add` → `Persistence/Migrations`, seed via `HasData`, `has-pending-model-changes` must be clean) — migrations are source-controlled; never hand-edit the DB. Aggregates implement the BCL-only marker `IHasDomainEvents` (Domain). **Reuse, don't reinvent** the DbContext/UoW/repo/dispatcher. Integration tests use **Testcontainers PostgreSQL** (require Docker; never mock `DbContext`) covering CRUD, real rollback, event dispatch, migration up/down. Details: `docs/backend/infrastructure.md` §1.1/§5.1.
- **Redis cache (Phase 12, closed):** `ICacheService` (Application port) is implemented **only** in `GameTeam.Infrastructure/Caching/RedisCacheService.cs` (StackExchange.Redis) — consumers depend on the port, **never** on StackExchange.Redis directly (no Redis type leaks out of Infrastructure). `CachingBehavior` runs **for real** on Redis (2nd identical cacheable query = cache hit). **Graceful degradation is mandatory:** a Redis failure (`RedisException`) or corrupt entry (`JsonException`) is **logged (warning) + degraded** (Get→miss/null so the caller runs the real source; Set/Remove→skipped) — never thrown to the API; Redis is **not** a single point of failure. Do **not** blanket-`catch (Exception)` (programming errors like `ArgumentNullException` must propagate). Connection from config key `ConnectionStrings:Redis` (env `ConnectionStrings__Redis`) — **never hardcode** host/port/password; `AddInfrastructure` fail-fasts if missing; `IConnectionMultiplexer` is a **singleton** (`AbortOnConnectFail=false`). Key convention (centralized in `RedisCacheKey`): `{env}:{domain}:{name}:{configVersion?}` — config version folds in so a config rollout invalidates stale reads (ADR-005: immutable `config@vN` = safe to cache long). **TTL is absolute expiry** (honor it — never make it app-only metadata). `Result`/`Result<T>` are cached via the STJ `ResultJsonConverterFactory` (Infrastructure `Serialization/`) — keep Domain free of JSON attributes. `/health` pings Redis (`ok`/`degraded`, HTTP 200). **Reuse, don't reinvent** `ICacheService`/`RedisCacheService` — don't add a second cache abstraction or a `RemoveAsync`-less duplicate. Integration tests use **Testcontainers Redis** (`redis:7-alpine`, require Docker; never mock Redis) covering set/get, TTL expiry, remove, down→degrade, and the CachingBehavior cache-hit. Details: `docs/backend/infrastructure.md` §2.1.
- **API layer (Phase 13, closed):** `GameTeam.Api` is the HTTP gateway + composition root. **Versioning** = `Asp.Versioning.Http` + `Asp.Versioning.Mvc.ApiExplorer` (8.1.1): `AddApiVersioning` (default **v1**, `UrlSegmentApiVersionReader`, `AssumeDefaultVersionWhenUnspecified`, `ReportApiVersions`) + `AddApiExplorer` (`SubstituteApiVersionInUrl=true` ⇒ OpenAPI renders `/api/v1/...`). Every new feature endpoint maps into the **version set** (`app.NewApiVersionSet().HasApiVersion(new ApiVersion(1))…Build()` + `MapGroup("/api/v{version:apiVersion}").WithApiVersionSet(set)` + `.MapToApiVersion(1)`) and stays **thin**: HTTP → `ISender.Send(command/query)` → Application `Result` → `ApiResults` → HTTP (no business logic in endpoints). **Never invent a second versioning convention.** **Centralized error handling** in `GameTeam.Api/Http/`: `ErrorHttpMapping` (the ONE `Error.Code`→HTTP-status table: `VALIDATION_FAILED`→400 + suffix convention `_NOT_FOUND`→404/`_CONFLICT`→409/`_UNAUTHORIZED`|`UNAUTHENTICATED`→401/`_FORBIDDEN`→403, default 400), `ApiResults` (`Result`/`Result<T>`→HTTP; failure→**`ErrorEnvelope`**; `traceId = Activity.Current?.Id ?? HttpContext.TraceIdentifier`), `GlobalExceptionHandler` (`IExceptionHandler` + `app.UseExceptionHandler()`; unhandled → **500 `ErrorEnvelope`** `INTERNAL_ERROR`, logs full exception server-side, **never leaks stack/exception/DB/internal detail**). **500 uses `ErrorEnvelope`, NOT ProblemDetails** — one error contract for all errors (Phase-05 §3); never invent a second envelope/`ErrorCode`, return a raw exception, or scatter mapping across endpoints. **Swagger UI** = `Swashbuckle.AspNetCore.SwaggerUI` (UI-only, **dev-only**) over first-party `/openapi/v1.json` — **no SwaggerGen** (first-party OpenAPI stays the single source → `shared/contracts/openapi.json` + drift guard + codegen). Any endpoint/contract change ⇒ rebuild (regenerate `openapi.json`) → `bash shared/codegen/run.sh` → commit generated diff → **add/extend an `Api.IntegrationTests` HTTP test** (status + contract + error envelope + versioned route). **Authentication is standardized (Phase 18, closed)** — see the dedicated Auth bullet below; reuse it, never build a second auth mechanism. `IConfigProvider` has a minimal `DefaultConfigProvider` placeholder (Infrastructure, `config@v1`) replaced by Phase 21's Config Service. `Program` stays `public partial class` for `WebApplicationFactory`. **Reuse, don't reinvent.** Details: `docs/backend/api-and-versioning.md` §3.1/§4.5.
- **Auth (Phase 18, closed):** `Account` (`GameTeam.Domain/Accounts/`, `AggregateRoot<Guid>`, `AccountType.Guest`, raises `AccountCreated`) is the **identity boundary** for server-authoritative state; provider linking (Google/Apple/email) is **Post-MVP** (future `account_providers` table — never add provider columns now). **Guest login** = `POST /api/v1/auth/guest` → `CreateGuestAccountCommand` (thin handler, `ITransactionalRequest`) → JWT (`sub`=account id, `type`=guest, `exp`) via the **`ITokenService`** port. **JWT lives ONLY in Infrastructure** (`JwtTokenService` HS256, `JwtOptions`) — Application depends on `ITokenService`, never a JWT framework (NetArchTest gates it). **Business endpoints are authenticated by default** (`AddAuthorization` `FallbackPolicy = RequireAuthenticatedUser` in `AddApi`; `UseAuthentication/UseAuthorization` on in `Program.cs`) — public endpoints are **explicitly** whitelisted with `.AllowAnonymous()` (health, `auth/guest`, openapi, swagger). Missing/invalid token → **401 `ErrorEnvelope`** (`UNAUTHENTICATED`). **Signing key** from secret/env `Jwt__SigningKey` via `IOptions<JwtOptions>` (fail-fast) — **never hardcode/commit/log** it; appsettings holds only issuer/audience/expiry. Later phases **reuse** this auth infra (add `.AllowAnonymous()` for new public endpoints; check resource ownership in handlers) — never a second auth mechanism, never fake a user, never bypass authz for convenience. Details: `docs/backend/api-and-versioning.md` §4.5 + `docs/backend/infrastructure.md` §2.5.
- **Profile / save root (Phase 19, closed):** `PlayerProfile` (`GameTeam.Domain/Profiles/`, `AggregateRoot<Guid>`, 1-1 with `Account` via `AccountId`) is the **server-authoritative save root** (ADR-007) that every future game-state feature **extends** (currency 31, hero 27/35, inventory 32, progress 34 — add tables/refs + **bump `SchemaVersion`**); Phase 19 adds **no business state** (`DisplayName`/`Level` are the defaulted Phase-05 `ProfileDto` fields). `GET /api/v1/profile` → **`GetOrCreateProfileCommand`** (`ITransactionalRequest`: get-or-create + read-repair `Upgrade`, atomic); pure read = `GetMyProfileQuery` (→ `PROFILE_NOT_FOUND`). **Ownership is resolved ONLY from the token `sub`** via the **`ICurrentUser`** port (`Abstractions/Security/`; adapter `GameTeam.Api/Auth/CurrentUser.cs` over `IHttpContextAccessor`, registered in `AddApi` with `AddHttpContextAccessor`) — **never** trust a client-supplied account/profile id (body/route/query) ⇒ no IDOR. Repository via **`IPlayerProfileRepository`** (`GetByAccountIdAsync`; never leak `IQueryable`) → `PlayerProfileRepository`. Table **`player_profiles`** (`snake_case`, **unique index `account_id`** + FK→`accounts` cascade) = **DB-level idempotency** (never check-then-insert); guest login creates `Account` + `PlayerProfile` in the **same transaction** (eager). **Schema versioning ≠ EF DDL migration:** `schema_version` per-row + `PlayerProfile.Upgrade()` (deterministic `v(N)→v(N+1)`, with a **data-preservation** test) is the profile **data** migration — any profile-schema change ⇒ **bump `SchemaVersion` + a `MigrateV{n}ToV{n+1}` step + a preservation test + an EF migration + doc-sync**, same change. The `/profile` endpoint was moved from the Phase-05 literal-`/api/v1` 501 stub into the **version set** (`.MapToApiVersion(1)`, protected by default). **Reuse, don't reinvent** the save root / current-user / profile mechanism; all profile mutation goes through a server command (server sets `schema_version`/`account_id`/owner/timestamps). Tests: Domain + Application unit + Testcontainers (persist/unique-constraint/dispatch/migrate) + Api.IntegrationTests (login→profile→`GET /profile` owner + authz). Details: `docs/backend/domain-and-application.md` + `docs/backend/infrastructure.md` §1.2 + ADR-007 (Implementation).
- **Configuration Service (Phase 21, closed — CLOSES P1):** the runtime SSOT for config lives in `GameTeam.Infrastructure/Configuration/` (ADR-005). Pipeline: `config/ → validate → build immutable bundle `config@vN` → persist (DB) + cache (Redis) → flip "current" atomically → serve via `IConfigProvider``. **`IConfigProvider` = `RuntimeConfigProvider`** (replaces the Phase-13 `DefaultConfigProvider`): holds an immutable in-memory `ConfigSnapshot` swapped atomically; `CurrentVersion` + `Get<T>(type,id)` + `GetIds(type)` are **synchronous / no-I/O**. Domain/Application read config **ONLY** through the port — **never** the filesystem (grep guard: no `File.`/`Directory.`/`Path.`). **Validate reuses the Phase-07 core lib** (`ConfigValidationRunner`/`ConfigLoader` via ProjectReference — one validation source, never fork a second validator); **cache reuses the Phase-12 `ICacheService`** (key `config-bundle:config@vN`, immutable, long TTL); persistence = `config_bundles` (immutable rows, one per version) + `config_current` (singleton pointer) via `AppDbContext` + migration `AddConfigBundles`. **`ConfigBundleBuilder`** computes a **deterministic SHA-256 checksum** over canonical `{schema_version,data}` (order-independent, excludes `generated_at`) ⇒ **dedup** (unchanged config never bumps). **`ConfigBundlePublisher`**: validate → fail ⇒ **NO publish** (current unchanged, invalid never served) → build → dedup → new version = current+1. **`ConfigBundleStore.SaveAndPublishAsync`** inserts the bundle + flips the pointer in **ONE transaction** (atomic — "current" only ever names a fully-built bundle), warms Redis after commit. **Deploy-time publish** = `ConfigPublishHostedService` (`IHostedService`, runs once at boot, **best-effort/graceful degradation** — never crashes the host). **Endpoints** (version set, `.AllowAnonymous`): `GET /api/v1/config/current` (→ `ConfigBundleDto`) + `GET /api/v1/config/bundle?bundleVersion=N` (verbatim payload; unknown ⇒ 404 `CONFIG_BUNDLE_NOT_FOUND`; param is `bundleVersion` — not `version` — to dodge the `{version:apiVersion}` collision). **Reuse, don't reinvent** the provider/publisher/store/validator; a config change ⇒ a **new version served with no client rebuild**; keep old versions (rollback foundation). Out of scope: client bundle e2e/caching = phase 22, typed gameplay POCOs = phases 27+, live swap = Post-MVP, feature flags/A-B = phase 49. Tests: `ConfigBundleBuilderTests` (unit checksum) + Testcontainers `ConfigServiceIntegrationTests` + `ConfigEndpointTests`. Details: `docs/backend/infrastructure.md` §3.1.
- **Combat sim (Phase 24, closed — opens Group 5):** the **pure, deterministic** combat simulator is the server-authoritative source of truth for battle results (ADR-011). **Pure engine in `GameTeam.Domain/Combat/`** (package-free — guarded by `Domain_should_not_depend_on_framework_packages` + `Combat_domain_sim_should_not_depend_on_framework_or_persistence`): `BattleSimulator.Simulate(BattleInput) → BattleOutput`; `Numerics/FixedPoint` (`long`, `FixedScale=1000`, **single** round-half-up law, div-by-zero/negative guards — **no `float`/`double`**), `Rng/Pcg32` (PCG32 `pcg_setseq_64_xsh_rr_32` + SplitMix64, explicit `ulong` seed, **one stream/battle**, `unchecked` wrapping 64-bit, logical shifts — **no global RNG**), `Model/*` (self-contained `BattleInput`), `State/UnitState`, `Events/*` (13 types; `seq` by list position; golden field names), `Effects/*` (`EffectRegistry` `effect_type`→`IEffectHandler`; sample `DamageEffectHandler`/`HealEffectHandler`; unknown type throws; **never `switch(skillId)`** in the core), `Serialization/CombatEventSerializer` (deterministic compact JSON). **No I/O, no wall-clock (the sim needs no `IClock`), no `float`/`double`, no global RNG.** **Data-driven layer in `GameTeam.Application/Combat/`**: `CombatInputResolver` reads hero/skill/stage via **`IConfigProvider`** → builds `BattleInput` (change a config value ⇒ result changes with no code change — ADR-004); combat config POCOs live here (`combat_rules` sourced from **stage config** — schema formalization is a follow-up). **No battle endpoint** (phase 30). Implement spec §9–§20 (don't re-decide); golden `vector_01`/`vector_02` match bit-for-bit, determinism N=200. Energy/ultimate (§15, CB4 `[ĐỀ XUẤT]`) is wired but inactive — don't activate/close without product. **Reuse, don't reinvent** the engine/registry; the phase-25 client sim must match the server. Guards: `CombatPuritySourceScanTests` (bans float/double/DateTime/RNG-global) + NetArchTest for the combat namespace; tests are the contract (Domain 77 / Application 45, no Docker needed). Details: `docs/gameplay/combat-framework.md` §21.
- **No hardcoded gameplay balance** — read via config port (ADR-004/005). No direct config-file reads in Domain/Application.
- **Central Package Management** (ADR-010): versions in `Directory.Packages.props`, csproj references are version-less. New dependency ⇒ justify in PR.
