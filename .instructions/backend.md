# Instructions: Backend scope (`server/`)

Short execution hints. Canonical design: `docs/backend/`. Agent: `.claude/agents/dotnet-backend`.

- Clean Architecture + CQRS/MediatR; dependency direction **inward only** (`docs/architecture/dependency-graph.md`).
- Domain is pure — no EF/HTTP/`DateTime.Now`. Inject `IClock`; use server time.
- **Domain foundation (Phase 09, đã chốt):** reuse primitives in `GameTeam.Domain/Common/` — `Result`/`Result<T>`, `Error` (stable `SCREAMING_SNAKE_CASE` code, `Error.None`), `Entity<TId>` (identity equality), `ValueObject` (value equality), `AggregateRoot<TId>` (owns domain events: `RaiseDomainEvent`/`DomainEvents`/`ClearDomainEvents` — **raise+collect only, no dispatch**; dispatch = phase 10/11), `IDomainEvent`, `IClock` (`DateTimeOffset UtcNow`), `Guard` (NotNull/Positive/InRange **throw** BCL argument exceptions). **Do NOT** re-invent these or add EF/HTTP/MediatR to Domain. **Result** = expected business failures; **exceptions/Guard** = programming/invariant/infra. `GameTeam.Domain` stays package-free — NetArchTest `Domain_should_not_depend_on_framework_packages` gates it. `IClock` lives in Domain (not Application).
- **Application pipeline (Phase 10, đã chốt):** cross-cutting ở **MediatR pipeline behaviors**, KHÔNG rải trong handler; handler **mỏng**. Behaviors ở `GameTeam.Application/Behaviors/`, thứ tự cố định **`Logging → Validation → Transaction → Caching`** (đăng ký trong `AddApplication`; `PipelineOrderTests` khoá thứ tự — đừng chỉ tin thứ tự đăng ký). Validation fail → `Result` lỗi (`VALIDATION_FAILED`), **không** ném thô. Transaction chỉ bao **`ITransactionalRequest`** (query KHÔNG vào transaction); Caching chỉ bao **`ICacheableQuery`** (key = tên+tham số+config version). Logging **không** log body/nhạy cảm. Ports ở Application (`IUnitOfWork`, `IRepository<TEntity,TId>`, `ICacheService`, `IConfigProvider`) — Infrastructure hiện thực (11–12/21); `IClock` dùng lại Domain. **Reuse, đừng phát minh** behavior/port/Result mới; mọi command/query mới đi qua pipeline. Chi tiết: `docs/backend/cross-cutting.md` §2.5.
- **Persistence EF Core (Phase 11, đã chốt):** EF Core/Npgsql **CHỈ** ở `GameTeam.Infrastructure` (NetArchTest `Application_should_not_depend_on_efcore_or_npgsql` + Domain purity gác cổng — đừng làm yếu). Nguồn: `GameTeam.Infrastructure/Persistence/` — `AppDbContext` (override `SaveChangesAsync` **dispatch domain event** qua MediatR `DomainEventNotification<T>`/`IPublisher`, sau persist & trong transaction), `EfRepository<TEntity,TId>` (chỉ `GetById`/`Add`; **KHÔNG** rò `IQueryable`/`DbSet`/`DbContext` ra ngoài), `UnitOfWork` (`Begin/Commit/Rollback`; port **không** có SaveChanges ⇒ **Commit tự SaveChanges** rồi commit tx). EF config tách **một `IEntityTypeConfiguration<T>`/entity**, bảng/cột **`snake_case` tường minh**. Connection string **từ config** khoá `ConnectionStrings:Postgres` (env `ConnectionStrings__Postgres`) — **KHÔNG hardcode credential**. Schema thay đổi đi qua **migration** (`dotnet ef migrations add` → `Persistence/Migrations`; seed dùng `HasData`; `has-pending-model-changes` phải sạch) — migration là artifact source-controlled, **KHÔNG** sửa DB thủ công. Aggregate hiện thực marker BCL-only **`IHasDomainEvents`** (Domain) để dispatch phát hiện event. **Reuse, đừng phát minh** DbContext/UoW/repo/dispatcher thứ hai. Chi tiết: `docs/backend/infrastructure.md` §1.1/§5.1.
- **Persistence test (Phase 11):** integration bằng **Testcontainers PostgreSQL** (`postgres:16-alpine`) — **KHÔNG** mock DbContext để thay; phủ CRUD, **rollback thực**, **domain-event dispatch**, migration up/down. Yêu cầu Docker (CI ubuntu có sẵn; local `scripts/dev/up`); không skip. Entity mẫu ở assembly test (`TestDbContext : AppDbContext`) để giữ schema production sạch. Nguồn: `GameTeam.Infrastructure.Tests/Persistence/`.
- **Redis cache (Phase 12, đã chốt):** `ICacheService` hiện thực **CHỈ** ở `GameTeam.Infrastructure/Caching/RedisCacheService.cs` (StackExchange.Redis) — consumer phụ thuộc **port**, KHÔNG phụ thuộc StackExchange.Redis trực tiếp (không rò kiểu Redis ra ngoài Infrastructure). `CachingBehavior` chạy **thật** với Redis (query lần 2 = cache hit). **Graceful degradation BẮT BUỘC:** lỗi Redis (`RedisException`) / entry hỏng (`JsonException`) ⇒ **log warning + degrade** (Get→miss ⇒ chạy nguồn thật; Set/Remove→bỏ qua), KHÔNG ném lên API; Redis **không** là điểm chết đơn. **KHÔNG** `catch (Exception)` mù (lỗi lập trình `ArgumentNullException`… phải propagate). Connection từ config `ConnectionStrings:Redis` (env `ConnectionStrings__Redis`) — **KHÔNG hardcode**; `AddInfrastructure` fail-fast khi thiếu; `IConnectionMultiplexer` **singleton** (`AbortOnConnectFail=false`). Quy ước key (tập trung ở `RedisCacheKey`): `{env}:{domain}:{name}:{configVersion?}` — gấp config version ⇒ rollout config tự vô hiệu cache (ADR-005: `config@vN` bất biến ⇒ cache dài an toàn). **TTL là absolute expiry** — tôn trọng, không biến thành metadata app-only. `Result`/`Result<T>` cache qua `ResultJsonConverterFactory` (STJ, `Serialization/`) — giữ Domain sạch (không attribute JSON). `/health` ping Redis (`ok`/`degraded`, HTTP 200). **Reuse, đừng phát minh** `ICacheService`/`RedisCacheService`. Test: **Testcontainers Redis** (`redis:7-alpine`, yêu cầu Docker; KHÔNG mock) phủ set/get, TTL hết hạn, remove, down→degrade, CachingBehavior cache hit. Chi tiết: `docs/backend/infrastructure.md` §2.1.
- **API layer (Phase 13, đã chốt):** `GameTeam.Api` = cổng HTTP + composition root. **Versioning** = `Asp.Versioning.Http` + `Mvc.ApiExplorer` (8.1.1): `AddApiVersioning` (default **v1**, `UrlSegmentApiVersionReader`) + `AddApiExplorer` (`SubstituteApiVersionInUrl` ⇒ OpenAPI render `/api/v1/...`). Endpoint mới map vào **version set** (`app.NewApiVersionSet()…Build()` + `MapGroup("/api/v{version:apiVersion}").WithApiVersionSet(set)` + `.MapToApiVersion(1)`) — **KHÔNG** tự tạo convention version khác; `ApiVersions` vẫn là hằng số version. **Endpoint MỎNG qua MediatR**: HTTP → `ISender.Send` → Application `Result` → `ApiResults` → HTTP; KHÔNG nhét nghiệp vụ vào endpoint. **Xử lý lỗi tập trung** ở `GameTeam.Api/Http/`: `ErrorHttpMapping` (MỘT bảng `Error.Code`→status: `VALIDATION_FAILED`→400 + suffix `_NOT_FOUND`/`_CONFLICT`/`_UNAUTHORIZED`/`_FORBIDDEN`, default 400), `ApiResults` (`Result`/`Result<T>`→HTTP, failure→**`ErrorEnvelope`**, `traceId`=`Activity.Current?.Id ?? TraceIdentifier`), `GlobalExceptionHandler` (`IExceptionHandler`+`UseExceptionHandler` ⇒ unhandled→**500 `ErrorEnvelope`** `INTERNAL_ERROR`, log server-side, **KHÔNG lộ stack/nội bộ**). **500 dùng `ErrorEnvelope`, KHÔNG ProblemDetails** — MỘT error contract (Phase 05 §3); **KHÔNG** chế envelope/ErrorCode thứ hai, **KHÔNG** trả exception thô. **Swagger UI** (`Swashbuckle.AspNetCore.SwaggerUI`) **chỉ** render OpenAPI first-party `/openapi/v1.json` ở **dev** — **KHÔNG SwaggerGen** (giữ single-source + drift guard). Thêm/đổi endpoint ⇒ rebuild (regenerate `openapi.json`) → `bash shared/codegen/run.sh` → **thêm `Api.IntegrationTests`** (status+contract+error envelope+versioned route). **Auth = Phase 18 (đã chốt)**: xem bullet Auth riêng bên dưới — tái dùng, KHÔNG dựng cơ chế auth thứ hai. `IConfigProvider` có placeholder `DefaultConfigProvider` (Infra, config@v1) → Phase 21 thay. `Program` giữ `public partial class` cho `WebApplicationFactory`. **Reuse, đừng phát minh.** Chi tiết: `docs/backend/api-and-versioning.md` §3.1/§4.5.
- **Auth (Phase 18, đã chốt):** `Account` (`Domain/Accounts/`, `AggregateRoot<Guid>`, `AccountType.Guest`, raise `AccountCreated`) = **ranh giới định danh** cho state server-authoritative; provider linking = **Post-MVP** (bảng `account_providers` tương lai — đừng thêm cột nay). Guest login `POST /api/v1/auth/guest` → `CreateGuestAccountCommand` → JWT (`sub`/`type`/`exp`) qua port **`ITokenService`**. **JWT chỉ ở Infrastructure** (`JwtTokenService` HS256, `JwtOptions`) — Application phụ thuộc `ITokenService`, KHÔNG thư viện JWT (NetArchTest gác). **Endpoint nghiệp vụ mặc định yêu cầu auth** (`FallbackPolicy=RequireAuthenticatedUser` ở `AddApi`; `UseAuthentication/UseAuthorization` bật ở `Program.cs`); public phải **whitelist tường minh** `.AllowAnonymous()` (health/auth/openapi/swagger). Thiếu/sai token → **401 `ErrorEnvelope`** (`UNAUTHENTICATED`). **Key** từ secret/env `Jwt__SigningKey` (fail-fast) — **không** hardcode/commit/log; appsettings chỉ issuer/audience/expiry. Phase sau **tái dùng** (thêm `.AllowAnonymous()` cho endpoint public mới; kiểm sở hữu tài nguyên trong handler) — KHÔNG cơ chế auth mới, KHÔNG fake user, KHÔNG bypass authz. Chi tiết: `docs/backend/api-and-versioning.md` §4.5 + `docs/backend/infrastructure.md` §2.5.
- **Profile / save root (Phase 19, đã chốt):** `PlayerProfile` (`Domain/Profiles/`, `AggregateRoot<Guid>`, 1-1 với `Account` qua `AccountId`) = **gốc save server-authoritative** (ADR-007) mà mọi feature state sau **mở rộng** (currency/hero/inventory/progress — thêm bảng/ref + **bump `SchemaVersion`**); Phase 19 KHÔNG thêm state nghiệp vụ. `GET /api/v1/profile` → **`GetOrCreateProfileCommand`** (get-or-create + read-repair migrate, atomic — `ITransactionalRequest`); read thuần = `GetMyProfileQuery` (→`PROFILE_NOT_FOUND`). **Ownership CHỈ từ token `sub`** qua port **`ICurrentUser`** (adapter `GameTeam.Api/Auth/CurrentUser.cs` trên `IHttpContextAccessor`, đăng ký ở `AddApi`) — **KHÔNG** tin id client (body/route/query) ⇒ chống IDOR. Repo qua port **`IPlayerProfileRepository`** (`GetByAccountIdAsync`, không rò `IQueryable`). Bảng `player_profiles` (`snake_case`, **unique index `account_id`** + FK→`accounts`) ⇒ **idempotency ở tầng DB** (KHÔNG check-then-insert); guest login tạo `Account`+`PlayerProfile` **cùng transaction** (eager). **Versioning ≠ EF migration:** `schema_version` per-row + `PlayerProfile.Upgrade()` (`v(N)→v(N+1)`, deterministic, có **test preservation**) là migrate **dữ liệu**; đổi cấu trúc profile ⇒ **bump version + bước `MigrateV{n}ToV{n+1}` + test giữ dữ liệu + EF migration + doc-sync** cùng change. Endpoint đã chuyển từ stub 501 (literal `/api/v1`) vào **version set** (`.MapToApiVersion(1)`, protected mặc định). **Reuse, đừng phát minh** save root / current-user / profile mechanism thứ hai; mọi mutation qua command server. Test: Domain + Application (unit) + Testcontainers (persist/unique/dispatch/migrate) + Api.IntegrationTests (login→profile→`GET /profile` owner/authz). Chi tiết: `docs/backend/domain-and-application.md` + `docs/backend/infrastructure.md` §1.2 + ADR-007.
- **Configuration Service (Phase 21, đã chốt — ĐÓNG P1):** runtime SSOT cho config ở `GameTeam.Infrastructure/Configuration/` (ADR-005). Pipeline `config/ → validate → build bundle bất biến config@vN → persist (DB) + cache (Redis) → flip "current" nguyên tử → IConfigProvider`. **`IConfigProvider` = `RuntimeConfigProvider`** (thay `DefaultConfigProvider`): snapshot bất biến trong bộ nhớ, `CurrentVersion`/`Get<T>(type,id)`/`GetIds` **đồng bộ, không I/O**. Domain/Application đọc config **CHỈ** qua port — **không** `File.`/`Directory.`/`Path.` (grep guard). Validate = **tái dùng core lib Phase 07** (`ConfigValidationRunner`/`ConfigLoader` qua ProjectReference — KHÔNG fork validator thứ 2); cache = **tái dùng `ICacheService` Phase 12** (key `config-bundle:config@vN`, immutable, TTL dài); persist = `config_bundles` (immutable, một row/version) + `config_current` (con trỏ singleton) qua `AppDbContext`/migration. Checksum SHA-256 **xác định** (dedup: config không đổi ⇒ không bump). **Publish khi deploy** = `ConfigPublishHostedService` (`IHostedService`, best-effort/graceful — không sập host). **Atomic:** flip "current" **cuối cùng, trong transaction persist**. **Validator-fail ⇒ KHÔNG publish** (current giữ nguyên). Endpoint (version set, `.AllowAnonymous`): `GET /api/v1/config/current` + `GET /api/v1/config/bundle?bundleVersion=N` (nguyên văn; 404 `CONFIG_BUNDLE_NOT_FOUND`; param `bundleVersion` tránh trùng `{version:apiVersion}`). **Reuse, đừng phát minh** provider/publisher/store/validator thứ 2; đổi config ⇒ **version mới, không rebuild client**; giữ version cũ = nền rollback. Ngoài scope: client bundle e2e = phase 22, typed POCO = phase 27+, live swap/flags = Post-MVP/phase 49. Test: `ConfigBundleBuilderTests` (unit) + Testcontainers `ConfigServiceIntegrationTests` + `ConfigEndpointTests`. Chi tiết: `docs/backend/infrastructure.md` §3.1.
- **Combat sim (Phase 24, đã chốt — mở Nhóm 5):** lõi sim **thuần, tất định** = nguồn chân lý kết quả trận (ADR-011). **Lõi ở `GameTeam.Domain/Combat/`** (package-free): `BattleSimulator.Simulate(BattleInput)→BattleOutput`; `Numerics/FixedPoint` (long, `FixedScale=1000`, round-half-up **một luật**, guard chia-0/âm — **cấm float/double**), `Rng/Pcg32` (PCG32+SplitMix64, seed `ulong` tường minh, **một stream/trận**, `unchecked` wrap 64-bit, **KHÔNG** RNG global), `Model/*` (`BattleInput` tự chứa), `State/UnitState`, `Events/*` (seq theo vị trí, khớp golden format), `Effects/*` (`EffectRegistry` `effect_type`→`IEffectHandler`; `DamageEffectHandler`/`HealEffectHandler` mẫu; unknown ⇒ ném; **KHÔNG** `switch(skillId)`), `Serialization/CombatEventSerializer`. **Không I/O, không wall-clock (sim không cần `IClock`), không `float`/`double`.** **Tầng data-driven ở `GameTeam.Application/Combat/`**: `CombatInputResolver` đọc hero/skill/stage qua **`IConfigProvider`** → dựng `BattleInput` (đổi config ⇒ kết quả đổi, không sửa code — ADR-004); config POCO ở đây (`combat_rules` **nguồn stage config**, hình thức hoá schema = follow-up). **KHÔNG** endpoint (phase 30). Bám spec §9–§20 (KHÔNG tự quyết lại); golden `vector_01/02` khớp bit-for-bit, determinism N=200. Năng lượng/ultimate (§15, CB4 `[ĐỀ XUẤT]`) nối sẵn nhưng **chưa kích hoạt**. **Reuse, đừng phát minh** engine/registry thứ 2; client (phase 25) phải khớp server. Guard: `CombatPuritySourceScanTests` (cấm float/double/DateTime/RNG global) + NetArchTest lõi combat; test = hợp đồng (Domain 77 / Application 45, không cần Docker). Chi tiết: `docs/gameplay/combat-framework.md` §21.
